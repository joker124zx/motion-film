# 节奏：为观众计时

你知道发生了什么，因为代码是你写的。观众不知道：他们只看一次、全速、第一次看。
**每个时刻问：观众此刻需要读懂什么、需要多久，按这个计时。**

## 1. Reads（信息点）

- 每个镜头按顺序列出观众要读懂的东西，每条是一个 read，各有起止时间。
- 每个 read 需要：眼睛找到它的时间 + 理解它的时间 + 落地的一小会儿，然后下一件事才开始。小的、远的、快的、微妙的东西比大的、居中的、明显的更花时间。
- **一次一个 read。** 两件事同时发生，观众只看见一件。因与果按顺序放，不叠在一起。
- **快动作，慢含义。** 有预备的动作可以很快；它的意义需要停住的时间。
- **引导视线。** 观众看会动的、亮的、大的、被别人看着的东西。重要 read 之前先把眼睛带到位（角色看过去、相机移过去、它先动或先亮），并给眼睛移动的时间。
- **reads 决定时长。** read 多的镜头不能短；read 都落地了就别硬撑。最后一个镜头的最后一个 read 也要在片子结束前落地。
- 镜头 reads 塞不下：加长镜头或删一个 read，别挤。

## 2. 停留时间公式（硬下限）

| 内容 | 下限 |
|---|---|
| 字幕 | ≥ max(1.8 s, 语音时长 + 0.6 s) |
| 画面文字（入场动画结束后起算） | 中文 ≈ 字数 ÷ 4.5 + 1.5 s；英文 ≈ 字母数 ÷ 15 + 1.5 s；混排相加 |
| 标题卡 | ≥ 4 s（短片里的品牌标题字卡可以 ≥ 2.5 s） |
| 品牌字标 / logo 落定 | 静止 ≥ 1 s 再切 |
| 批量元素入场完成 | 静止 ≥ 0.5 s 再切 |
| 开场主体完整动作弧 | ≥ 3 s |
| 判断画面（物体 + 阈值 + 结论同框） | ≥ 2.5 s |
| 结尾画面 | 0.8–1.2 s 带微动；有标语/URL 再加阅读时间 |

要快，就减少每屏的字，而不是在观众读完前切走。
可选自动检查：页面暴露 `window.TEXTS(t)` 返回当前可见文字，`render.mjs --readcheck` 会报出停留不足的文字。

## 3. 节奏的形状

- **变速**：快慢交替，至少一次明显的加速或减速，至少一次呼吸（长镜头或刻意停顿）。一个速度到底的片子是失败的——不管是一直快还是一直慢。
- **能量曲线**：低能量开场（一个主角）→ 功能/内容段与呼吸位交替 → 高能量收尾。卡点片的 breakdown 天然是呼吸位。
- **加速度带来速度感，不是匀速快。** 大量同类元素入场用“越来越快”的硬加速（最好挂一个物理隐喻，如发牌），满板后静止 0.5 s。抽象的“一大片涌进来”很难调好，换成发牌/堆叠/掉落这类隐喻往往一轮通过。
- **模拟真实交互**（打字、筛选、点击）按真人操作速度，观众要能跟着做一遍。
- 一个动作一个声音一个切点，但不要每拍都切。留时间看。
- **宁慢勿快**：在多支片子的返工记录里，节奏反馈几乎全部指向“放慢/多停一会”，极少有“太慢了”。排时间线时先预留 hold/rest 的帧预算，别把动效排满每一帧。

## 4. 检查节奏的方法

单帧判断不了节奏，要像观众一样读：

1. 把镜头按固定步长（0.1–0.15 s）出一张接触印样，按顺序读。
2. 每一帧问：观众此刻在看哪里？读懂了吗？
3. 数每个 read 得到的帧数（24 fps 下 24 帧 = 1 s）。只闪几帧、或和别的 read 共用帧的，会被错过。
4. 每个重要时刻之后，有没有时间消化再开始下一件事？
5. 最后全速带声看一遍。

## 5. 案例：一个结尾怎么计时

| 时间 | read | 为什么这样排 |
|---|---|---|
| 6.95–7.10 | 蓄力、投出 | 快动作；有预备所以读得懂 |
| 7.10–7.90 | 星星飞回天上 | 够眼睛从角色追到画面顶部；相机缓退给天空留位置 |
| 7.90–8.35 | 星星到位：闪光、星空闪烁 | 回报时刻；角色只是看着，没有东西抢 |
| 8.35–8.95 | 角色被打动 | 观众看到“因”之后才开始“果” |
| 8.95–9.40 | 挥手告别 | 新动作，单独一个 |
| 9.40–9.80 | 星星眨眼回应 | 对挥手的回答 |
| 9.80–11.0 | 光圈收向角色、停住、关闭 | 最后一个 read 落地后才结束 |

第一版把这一切塞进了约 1.3 s，没人看得懂发生了什么。
