# 审美准则（判例式）

每条 = 规则 + 为什么（来自真实返工）+ 自检问题。自检时逐条输出 `编号 ✓` 或 `编号 ✗（镜头/帧号）`。
准则可以有意识违反（风格需要），但要在 TREATMENT.md 里写明违反了哪条、为什么。
标 **[产品]** 的条目主要针对产品宣传片，其余通用。

## 节奏 R

**R1 关键信息落定后必须呼吸。** 想让观众记住的画面（品牌字标、核心数字、全貌）落定后静止 ≥ 1 s 再切。停顿给品牌/关键信息，不给普通元素。
为什么：返工最多的就是“停一下”，而且常常停错了对象。
自检：每个“想让人记住的画面”有没有完整的静止时刻？停顿给对了对象吗？

**R2 速度感来自加速度。** 飞入、滚动一律非线性缓动 + 非均匀错峰；匀速运动读作廉价 PPT。批量入场越来越快、挂物理隐喻、收尾静止 0.5 s。
为什么：抽象的“涌入”调五轮不收敛，换成发牌隐喻一轮通过。
自检：有没有元素在匀速直线运动？批量入场是否越来越快、末尾有呼吸？

**R3 宁慢勿快。** 开场主体动作弧 ≥ 3 s；交互演示按真人速度；第一版默认再放慢一档。
自检：当成第一次看，哪里没看清？交互段我能跟着操作一遍吗？

**R4 卡点管时机，不放大幅度。** 作用于整画面或相机层的节拍冲击（整体 scale 泵、震屏、闪帧、负片帧）全片 ≤ 3 处，钉在最强的几个鼓点上，相邻两处间隔 ≥ 16 拍；节拍泵连打单次 ≤ 4 拍、全片 ≤ 1 次。其余拍点只动主角元素层。鼓点命中表是候选池，不是触发器。一次手法使用算一个名额（三连闪算一次）。
为什么：强鼓点曲几乎每拍都有 kick，逐拍“砸”画面 = 镜头随节奏抖，观众直接投诉。
自检：高能段任取 8 拍逐帧看，整画面在逐拍脉冲吗？全画面冲击数超过 3 了吗？

## 质感·运镜·构图 Q

**Q1 [产品] 复刻既有页面用真实截图。** 表现产品真实页面的镜头，第一步就截真实页面（整页 2x + 元素切图 + 坐标表）。手搓 UI 只用于非复刻场景（抽象开场、品牌段、页面上不存在的展示组件），且质感必须达到出版级、观众一眼看懂它是什么，否则回截图路线。
为什么：一下午手搓复刻的页面整体作废——观众要看的是“真的产品在动”。

**Q2 3D/放大下文字发糊，先查栅格化链路，不先调相机或景深。** 透视下的 UI 纹理按显示尺寸 2–4 倍栅格化再缩小使用。Chromium 对 3D 合成层按布局尺寸栅格化后 GPU 放大，必糊；放大走 CSS `zoom`（布局级）而不是 `transform: scale`，并换算焦点坐标（`Tx = W/2/zoom − cx`）。全页 `deviceScaleFactor: 2`，主角元素单独 4x 截图，推近时 6 帧交叉淡入盖住低倍纹理。景深只做氛围，永远不是清晰度的解法。
自检：放大/透视镜头逐帧裁剪放大看字边缘，有没有像素方块？

**Q3 镜头要稳。** 亮场 UI/产品片禁用手持抖动；相机噪声只在暗场纪实感片子里用极小值，并自查渲染帧。冲击时的短促震动可以，但计入 R4。

**Q4 光效宁缺毋滥。** glint/扫光/泛光不群发，一个镜头最多给主角一次，必须被承载元素的圆角裁剪（光溢出圆角是廉价感的典型来源）。手法本身不禁：单点、给主角、实现过硬的可以做，做完正常速度回放问自己“好看吗”。

**Q5 开场只给一个主角。** 一个主体 + 一条完整动作弧（例：聚光 → 推近 → 悬浮 → 描边光 → 归位），胜过多元素群舞。
为什么：开场推倒六次，改成单主角后直到成片再没动过结构。

**Q6 机位服务可读性。** 叙事/情绪镜头可倾斜；信息密集的列表/堆叠正视；含文字的卡片特写用侧向水平机位。不全局套用一种机位风格。

**Q7 物件特写做足环境戏。** 侧面倾斜机位 + 可感知的体积/高度 + 环绕运镜 + 与主场景反差的深色材质背景，再拉远过渡回主场景。死机位的物件特写没有分量。

**Q8 [产品] 结尾“发布会合影”。** 多功能产品收尾：每个已展示过的功能抽一个代表元素，多方向飞入围住字标定格；能量推到全片峰值（升降运镜 + 舞台光 + 粒子）。初版收尾几乎总是太保守，默认加码一档。

**Q9 飞入的终点是真实槽位。** 元素飞入后要嵌进布局（归位到格子、接进滚动流），不永久悬浮在页面上方。

**Q10 被读的 mock 内容要出版级。** 文档/报告/列表类镜头的假内容用原生排版、真实密度铺满，侧栏等版式元素完整入镜；“贴图 + 一句标语”的假页面整镜头返工。观众会暂停读每个字。

**Q11 文字有最低有效字高。** 1080p 成片按手机小窗校准：要读的字幕有效字高 ≥ 56 px（约 5% 帧高，推荐 60 px）；辅助文字（副标题、数据、URL）≥ 32 px（约 3%）。有效字高 = fontSize × 所有祖先 scale × 透视压缩，量渲染帧上的实际像素。文字只有两种状态：**纹理**（装饰小字，明显虚化或降亮，让人不去读）或**要读**（达标字号 + 足够对比，压在浅色上配衬底/投影）。没有“想让人读但读不清”的中间态——读不清就删。收尾 URL/行动号召是全片最不该小的一行。
自检：把含字幕的帧缩到 480 px 宽，还读得清吗？

**Q12 纯黑纯白慎用，同色不叠。** 用墨色代替纯黑、纸色/奶油色代替纯白（除非风格要求）；主体与背景明度分得开。

## 声音 S

**S1 配乐与音效按片种选，不按事件语义选。** 产品片：强鼓点、强节奏的电子底 + 电影系音效词汇（whoosh 运镜 / impact 落地 / riser 铺垫 / sparkle 光效 / transition 转场）；禁游戏音包**音色**（合成器 pluck/bloop、卡通弹跳、游戏结束音阶）。**禁的是音色不是动作**：画面里真有点击/开关/碎裂就配它的真实拟音。判别：这个音像真实世界里那个物件发出的声音，还是游戏引擎里的提示音？候选配乐必须垫进成片试听，单听曲子判断不了气质。风格片按该风格的声音调色板（见 style-atlas）。
为什么：“配乐和音效都太像游戏了”是产品片最常见的一票否决。

**S2 音效钉帧、集中建表。** 所有音效写在一张声明式表里：`{ t 或 at: 'cue+offset', src, gain, 注释对应的画面动作 }`。时间写相对表达式（相对镜头起点或拍号），不写裸帧号，时间线平移时自动跟随。连发防机枪感：双样本交替 + 音量阶梯递减（如 0.40 → 0.25）+ 间隔跟着动画加速；密到糊成一片时淡成一道 swoosh。

**S3 声音在画面锁定后做。** 任何改变镜头时长/顺序的修改，收尾必做“全表音效重对”。

**S4 拟音优先于装饰音。** 打字配键盘、逐条落入配逐个 pop、翻页配纸声；泛用 whoosh 盖不住有辨识度的动作。长样本按画面裁到与动作等长（带长尾混响的 impact 例外）；录得轻的素材换素材或先归一化，别指望音量系数救。

**S5 音画对齐补两项偏移。** ① 输出编码偏移：AAC 编码器 priming 常让整条音轨晚约 1024–2048 samples（30 fps 下约 1 帧多）——按自己的渲染管线实测一次（成片抽音轨与原尖锐音效做互相关），统一在时间计算里扣除；② 音源自身峰值滞后（峰值不在文件头）逐文件量：`起点 = 目标峰值时刻 − 峰值滞后 − 输出偏移`。卡点片差 2–3 帧就会被读作不同步。

**S6 至少两处真正的静音或近静音**，放在转折/情绪峰值之前；静音后的第一个声音应是全片最重要的声音之一。至少两次用声音做转场（J-cut 下一场声音提前进、L-cut 上一场声音拖过切点）。

## 文案 C

**C1 画面定稿后按最终镜头重写一遍文案。** 初稿只是占位。纯动画段配短解说，不留超过 3 s 的“哑巴段落”（品牌收尾镜头除外）——无字幕风格（如手绘角色片）则用表演代替。

**C2 [产品] 标语具体化。** 写“产品功能名 + 具体收益”，不写抽象隐喻口号（“一切尽在一处”类）。重要功能出场前可加一张引导字卡。

**C3 3D 镜头里的注记活在同一 3D 空间。** 同一台相机、同一透视、悬浮 + 落影；贴在屏幕玻璃上的平面字与场景脱节。

**C4 中文文案地道。** 用词自然、标点用全角中文标点、无错别字；数字在字幕里写阿拉伯数字，在 TTS 文本里写成汉字读法。

## 流程 P

**P1 不把首检交给用户。** 每轮修改先自己渲关键帧逐一检查（构图、抖动、文字锐度、穿帮），必要时裁剪放大 / 两帧 diff 自证。

**P2 参考素材先拆成手法清单**，逐项决定采用/弃用，不全局套用。

**P3 含糊的反馈先确认指代对象**（“第一个标题”是哪个？）；改错了整体回滚重来，不在错误版本上打补丁。每个改动保持独立、可回滚（用 git 或版本目录）。

**P4 先列内容清单逐一对应镜头。** [产品] 功能清单每项至少一个清楚可辨的镜头，漏拍等于返工。每个镜头问“它给了什么新信息”，重复即删。一种手法全片只当一次主角。

**P5 改动后的回归。** 每轮只改评审/用户点到的东西；不顺手“优化”已确认的部分；评审列为优点的不能退步。
