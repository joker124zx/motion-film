# 风格说明：写一种风格、改一种风格

风格说明（`STYLE.md`）只写**对这种风格的每一支片子都成立**的东西。故事、弧线、逐镜头表、开场结尾、配乐 BPM、样片的配色道具，都不属于风格，属于某一支片子的 TREATMENT。
样片里测出来的数字变成规则写进来（“主体至少占画面高度 1/3”）；写规则，不写历史。

## 1. STYLE.md 模板（11 节，节号固定）

```markdown
# <风格名> — 风格说明
> 一两句：这种媒介是什么、在屏幕上做什么。不写故事。
> 参考（只学语法）：哪些作品/艺术家/传统，各学什么。不抄、不在片中点名。

## 1. 本质，以及它不是什么
一眼认出这种风格的 3–5 个特征。再写容易混淆的风格和分界线（“不是 keynote、不是蓝图、不是产品渲染”）。

## 2. 材质与渲染
物理媒介是什么、代码怎么模仿它：表面、笔触、图层、边缘、肌理、光。渲染模型（图层、混合模式、噪声、笔触步进）。
哪些效果必须程序化并锚定在世界坐标，哪些在屏幕空间。

## 3. 色彩逻辑
写规则不写色板：几个色相、中性底是什么、强调色留给什么、明度怎么排、什么东西永远不上色。最多给一组示例色板并标明是示例。

## 4. 字体与字幕
字体（免授权费的，如 OFL）、角色（标题/字幕/微数据）、字号范围、字幕如何属于这个风格的世界（铭文、图注、HUD 面板……）、
阅读时间规则：停留 ≥ max(1.8 s, 语音 + 0.6 s)。

## 5. 运动质量
帧率与步进（一拍一/一拍二、什么在沸腾）、缓动族、重量、抖动、东西怎么出现消失、什么永远不动。

## 6. 运镜语法
| 运镜 | 表达什么 | 可以服务于 |
不指定开场/高潮/结尾必须用哪个。写永远成立的取景规则（主体大小、安全区、字在哪）。允许和禁止的转场。

## 7. 声音调色板
乐器与音色、演奏法、调式族、拟音材质（这种媒介的“物质”听起来像什么）、环境声、静音的用法、混音性格、人声性格。不写配乐结构和 BPM。

## 8. 原生动作（native moves）
只有这种媒介能做的瞬间，菜单式，片子按需取。每条：是什么、怎么做、**适合的内容**（至少三个，和样片不同）。

## 9. 媒介的陷阱
来自媒介本身的错误 + 修法。

## 10. 引擎
可复用的代码在哪（笔刷、rig、合成器、采样设置）、主要函数和参数、一个画样片里没有的东西的最小例子。

## 11. 变化空间
每支片子自己决定的（结构、角色、开场、结尾、运镜路线、节奏、色彩逻辑内的配色）。
然后各一行、都远离样片：三种结构、三种开场、三种结尾。
```

写好的关键：

- **标志特征要可检验**：写“过冲用 `cubic-bezier(0.34,1.56,0.64,1)`，错峰 2–4 帧”，不写“动效要有弹性”。
- 6–11 KB 足够；超过说明混进了某支片子的内容。

## 2. 单次提示词模板（快速出一支 10 s 风格片时）

不想写完整 STYLE.md、只想一次性做一支短片时，用这四段 + 通用尾巴：

```text
你是这支 <N> 秒动态设计短片的导演、动效设计、工程师和声音设计。
目标是这种风格最经典又最惊艳的形态；干净但像模板的结果算失败。

# Style
<中文风格名 English name>

# Output
<宽>×<高>, <fps> fps, exactly <N>.000 s, H.264 MP4 + stereo AAC 48 kHz, −14 LUFS integrated, true peak ≤ −1 dBTP.

# Suggested technical route
<SVG / Canvas / WebGL / Three.js / Blender…… 和关键实现手段>（有明显更好的路线可以换，说明理由）

# Creative seed
「一句话片名」+ 这种风格最经典的读法：
- 0–X s 发生什么（钩子 → 升级 → 高潮 → 结尾画面），按秒写
- 配色 3–6 个色值；字体气质
- Sound: 音乐风格 + 关键音效
你可以改概念、文案、节拍和品牌名，但结果必须是这种风格一眼可认的经典形态，并命中下面的标志特征。

# Signature features and key techniques（按这些验收）
<来源与用途一两句>
视觉特征：<逗号分隔>
关键技法：<每条一行，带参数>

# How to work
1. Treatment：一个清楚的点子——前 0.5 s 的钩子（开场空/黑不超过 0.3 s）、升级、约 60–75% 处一个明确的高潮、结尾画面停 0.8–1.2 s 带微动。每条标志特征对应到一个时刻。一张 cue 表，画面和声音都读它。
2. 先关键帧后运动：在 6–10 个时刻出静帧，真的看。每张都能当海报：构图、层级、留白、排版（字距、行高、字重对比、中文标点、约 5% 安全边距）。迭代到没有任何东西看起来默认、拥挤或像 AI 模板。
3. 运动：低分辨率预览，最快的动作逐帧看：间距、缓动、弧线、重叠、预备与跟随、运动模糊。没有意外的死区，能量跟着音乐。
4. 声音：片种正确的音乐和声音设计，锁在 cue 表上；视觉命中落在音频起音上；按输出规格母带。
5. 终检：全分辨率渲染后查——时长精确、分辨率、帧率、有音频且响度对、无黑帧、无回退字体或豆腐块、边缘无裁切、细线不闪、渐变无色带。
6. 诚实自评：最强的、最弱的、多给时间会做什么。

# Rules
确定性渲染（每帧是 t 的纯函数，种子随机）；素材只用 CC0/公有领域/OFL/明确免费商用并记进 CREDITS.md；不出现真实商标；画面中文地道、标点正确。
```

做完交给独立评审（`review.md`），按评审意见改一轮。

## 3. 改一种风格（做成用户自己的版本）

**从哪起**：改已有风格就以它为底；从空白做就先挑一个材质和引擎最接近的风格当“技法底子”，最多再从两个风格借动作，第一个问题就是“我选 X 当底子，因为……”。

**一次只问一个问题**，每题 2–3 个选项、推荐的排第一并说理由，最后一个选项是“直接聊”。约十个问题以内；用户说“你定”就按推荐填完，列一条消息确认。

**先讲清三组**（用这个风格自己的例子讲）：

| 组 | 对应章节 | 告诉用户 |
|---|---|---|
| 放心改 | §3 配色（在色彩逻辑之内）、§4 字体、§5 动作快慢与多少、§7 声音（乐器、密度）、§8 加或换一个原生动作 | 风格还是它自己；每项给 2–3 个方向 |
| 一改就变味 | §2 材质与画法、§3 色彩逻辑本身、§6 运镜语法 | 可以，但说清楚每个改动让风格失去什么 |
| 不能改 | §1 本质（含“它不是什么”）、§10 引擎 | 改了就是另一种风格，建议换更接近的底子 |

**把模糊的愿望翻译成具体选项**（不偷偷改）：

| 用户说 | 通常意味着 |
|---|---|
| 高级一点 | 颜色更少、明暗对比更强、动作更慢、留白更多、字重更轻 |
| 年轻 / 活泼 | 更亮的强调色、卡拍剪辑、更弹的缓动、更多打击乐 |
| 安静 | 更慢的速度、更长的停留、更少的运动元素、更稀疏的配器 |
| 像我们品牌 | 品牌色做强调色而不是底色；标题用品牌字体；logo 在开头和结尾 |

- 品牌：保留底子风格的明暗结构保证文字可读，品牌色先作为强调色进来。品牌字体必须覆盖片子的语言（中文片要有中文字形）并允许用于视频。logo 和字体由用户提供。
- 用户给了参考图/片：说出让它成立的两三件事，各对应到哪一节，哪些会碰到 §1。
- 原生动作是风格被认出来的依据：最多换一个。
- 联动的改动：动作变快 → 声音要更密；配色变暗 → 检查字的对比；换材质 → 把它的陷阱写进 §9。
- 一轮最多改五处。
- 只改故事、结构、开场结尾、角色、节奏、配音的，不需要新风格，做片时说就行。

**流程**：汇总（每项改前 / 改后 / 代价）→ 用户点头 → 写 `STYLE.md` 全文（不留“见底子”的空洞）+ `CHANGES.md` → 用真实绘制代码出风格帧，改已有风格的同一画面再按原风格出一张，左原右新并排 → 不满意改两轮还不对就直说，建议换底子 → 15–30 s 演示片，每个改动都在画面里出现，配音乐音效，自检修一轮 → 问用户固化 / 再改 / 先不固化。固化前一切只在项目文件夹里。
