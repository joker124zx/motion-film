# 评审：自检与独立评审

制作者对自己的作品有确认偏差。**首检永远不能交给用户，终检永远不能由制作者自己出。**

## 1. 制作中的自检（每轮都做）

- **接触印样**：每 0.5–1 s 一帧铺成一张图，看整片形状；至少完整过两遍。
- **动作条**：每个关键动作、转场、接缝，0.1–0.2 s 间隔逐帧铺开，看预备、跟随、跳帧、同步、匀速、对称。
- **裁剪放大**：脸、手、接触点、文字边缘、光效边缘，全分辨率看（缩略图上看不出糊和锯齿）。
- **全速带声看一遍。**
- 问：每个镜头的事件单看它那张印样能读懂吗？主体够大、和背景分得开吗？哪里有死区？有没有字？（无字风格）有没有意外的抖动？

`render.mjs` 的 `--sheet / --strip / --crop` 就是做这个的。预算：每个镜头至少一张印样，每个关键动作和转场一条动作条，每张承载故事的脸一次裁剪。

## 2. 规格检查（机器可查，`master.sh` 会报）

- 时长、分辨率、帧率精确；
- 有音轨，响度 −14 LUFS（±1）、真峰值 ≤ −1 dBTP；
- 无意外黑帧/空白帧、无 NaN 帧；
- 字体全部加载（无回退字体、无豆腐块）、图片完整加载；
- 元素不被画面边缘意外裁切；细线不闪烁；渐变无色带；
- 字幕与 `.srt` 同步、不挡关键动作；文字停留够长（`--readcheck`）；
- 卡点片：切点误差 ≤ 3 帧（beat-sync §4）。

## 3. 独立评审（交付前必做）

开一个**干净上下文**的评审者（subagent，或让用户另开会话）。只给它：成片路径、关键帧/印样、片子的规格要求（时长、画幅、风格标志特征或产品简报与必须展示的功能清单）、本文件和 `aesthetic-rules.md`。**不给**制作过程中的理由、修改历史、“应该没问题”的暗示。缺了某项输入就标“无法验证”，不让它猜。

### 评审提示词

```text
你是一位资深动态设计评委（动态设计媒体编辑、顶级动态设计工作室创意总监、头部设计类短视频账号负责人的水平）。
这支片不是你做的。为了让它达到获奖/高端商业水准，请严格而精确地评判——客气没有用，具体才有用。

成片：<路径>。要求：<风格名 + 输出规格 + 标志特征；或产品简报 + 必须展示的功能 + 视觉方向 tokens>。

1. 认真看片：抽一张接触印样（每 0.5 s 一帧）；在最快、最重要的动作和高潮附近抽动作条；在 5–8 个关键时刻取全分辨率帧。
   全分辨率看小细节：边缘、排版、锯齿、色带、肌理、裁切。
2. 查规格：时长精确、分辨率帧率、有音频、响度约 −14 LUFS、真峰值 ≤ −1 dBTP、无非预期黑帧或静止段、视觉命中对齐音频起音。
3. 各维度 1–10 分（5 = 合格学生作品；6 = 模板水平；7 = 扎实专业；8 = 高端代理商；9 = 获奖入围；10 = 世界最佳）。
   大多数首版应在 5–7，不要虚高。
   - style_fidelity 风格忠实（产品片：产品视觉一致性）：一眼可认，每条标志特征都在且做对
   - concept_wow 概念：清楚的点子、前 0.5 s 的钩子、明确的高潮、令人满意的结尾画面
   - motion_craft 动效：缓动、间距、重叠、预备与跟随、弧线、转场、运动模糊；无死动作、无抖动
   - design_typography 设计与排版：构图、层级、网格、排版（含中文）、配色、留白
   - finish_texture 质感：光、肌理、颗粒、辉光与细节符合风格；无色带、锯齿、瑕疵
   - sound_sync 声音：音乐性、片种正确、声音设计、音画同步、混音与母带
   - technical 技术：规格、字体加载、无故障/裁切/跳变
   - （产品片加）content 内容：功能清单每项都有清楚的镜头、无重复镜头/标语、无未经确认的功能宣称、数据已脱敏
4. 给 5–10 条修改，按对最终观感的影响排序。每条：时间码、问题（可观察的）、为什么重要、具体怎么改
   （技法和数字：缓动曲线、帧数、px、色值、字体、版式变化）。宁要几个大升级，不要一堆小毛病。至少一条要提升惊艳感，而不只是打磨。
5. 标为严重：任何看起来通用或像 AI 模板的地方、不自然的中文文案、回退字体或豆腐块、任何规格不合格、（产品片）漏拍的必须功能或暴露的敏感数据。
6. 按 aesthetic-rules.md 逐条给出 “编号 ✓” 或 “编号 ✗（时间码/帧号）”。

返回：评分表、严重问题、修改清单、准则逐条结果。每条结论附可复核的时间码或截图。
```

### 修改提示词（回到制作会话）

```text
独立评审的完整意见如下：<粘贴>
- 先把当前成片和源码另存为版本 N。
- 实现所有严重问题和所有高影响修改。有把握更好的解法可以替换，说明理由。看到更大的升级（尤其惊艳感）可以超出清单。
- 评审列为优点的不能退步。
- 全分辨率重渲、重查规格、看帧，直到修改真的落地。
- 报告：哪些改了、哪些没改、为什么。
```

## 4. 一轮修复规则

- 评审和规格检查发现的问题**一轮修完**，再查一次；那次复查发现的小问题（一个电平、一帧）属于同一轮。更大的问题在交付时用一句话告诉用户。
- 交付后用户的意见是新的轮次：只改用户要求的，不顺手重做别的。
- 修复按问题类型回到对应阶段：方向/分镜问题回 treatment，画面问题回实现，声音问题回声音。

## 5. 评分参考

| 维度低分时 | 最常见的根因 |
|---|---|
| concept_wow | 开场慢、没有钩子；没有一个只有这种媒介能做的瞬间；结尾不呼应 |
| motion_craft | 线性/匀速；所有部件同时动；无预备跟随；转场用 crossfade |
| design_typography | 默认字号字距；主体太小；层级不清；中文标点半角 |
| finish_texture | 渐变色带（加 3–5% 噪点）；细线闪烁（线宽 ≥ 1.5 px 或做超采样）；放大后糊（见 Q2） |
| sound_sync | 音效像游戏；没有静音；音画差 2–3 帧；低频过重 |
